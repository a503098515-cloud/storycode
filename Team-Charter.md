## 2 · The Product

**The problem:** Staying committed to learning programming is hard — traditional tutorials and disconnected practice problems make it easy to lose motivation, because the exercises don't feel connected to anything real or urgent.

**Who it's for:** Beginner-to-intermediate learners (self-taught coders, intro CS students) who've bounced off dry tutorial-style platforms and want the practice to feel like it's going somewhere, not just a checklist of unrelated problems.

**Three core features (the MVP):**

1. **Story mode with embedded challenges** — a branching narrative where progressing through each chapter requires solving a coding challenge tied to that scene's stakes (e.g., "the ship's navigation is down — write the function that fixes it").

---

2. **In-browser code runner with test feedback** — an embedded editor where a learner submits a solution and gets pass/fail feedback against test cases, framed as part of the story rather than a generic grader.

---

3. **Saved progress per user** — accounts that persist which chapters/challenges are completed, so a learner can leave and pick back up where they left off.

---

**What ships by Week 13 (demo day):** A stranger can create an account, play through at least one complete story arc (several chapters), solve the coding challenges gating each chapter's progression, and see their save persist across a session.

**Out of scope / v2 ideas (Week-9 pitch fodder):** Multiplayer/co-op story paths, leaderboards, multiple language tracks beyond one, achievement badges, AI-generated dynamic branching, mobile app.

## 4 · Code & Review Norms

**Branch & PR flow:** Create a new branch for each feature, test it and ensure reliability, create pull request

**What blocks approval:** Broken or unclear code, or unwanted changes

**Review response time:** 24 hours

**Comment conventions:** nit: for style/preference, q: for a genuine question, blocker: for something that has to change before merge.

## 5 · AI Working Norms

**Course policy (not optional):** no AI-generated code gets merged unread. The PR author owns every line they open, wherever it came from. AI explanations get verified by running the code.

**How we use AI as a team:** AI is fine for scaffolding, explaining unfamiliar code, and debugging — but every line in a PR has to be understood and tested by the person who opens it before it's up for review. If you can't explain why a line is there, it doesn't go in yet.

**What we never delegate to AI:** Architecture/schema decisions, and anything touching auth or user data — AI can draft a first pass, but a human designs it

## 6 · When Things Go Wrong

Stuck protocol (course default): 15 minutes stuck → post in the team thread → still stuck at stand-up → TA → office hours.

**If someone can't deliver on time:** Help them to ensure we get our work done, but also remind them of the expectations for the team

**If we have a conflict:** We discuss it or have a vote if necessary
